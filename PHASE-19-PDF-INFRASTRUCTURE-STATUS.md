# Phase 19 — PDF Infrastructure Status

## Status

**IMPLEMENTED — pending local dependency installation and runtime validation**

## Frozen scope implemented

The implementation follows the approved PDF stack:

- PDFKit for PDF document generation.
- HarfBuzz (`harfbuzzjs`) for Arabic/OpenType shaping.
- `bidi-js` for Unicode bidirectional text handling.
- Existing bundled Cairo fonts from `frontend/assets/fonts`.
- Electron/offline-compatible local assets and runtime dependencies.

The frozen MD requires one reusable PDF layer with shared identity, Arabic RTL, local font support, Client/Case/Service/Financial/Reports PDFs, and server-side financial authorization.

## Shared PDF service

`backend/src/services/pdf.service.js`

Provides:

- Shared A4 PDF document creation.
- Wathiqa logo.
- Office name.
- Office stamp when configured.
- Document title.
- Generation timestamp.
- Bundled Cairo font loading.
- HarfBuzz shaping.
- BiDi run ordering.
- RTL/LTR mixed text handling.
- Basic word wrapping.
- Multi-page flow.
- Shared footer.
- Safe office-asset path handling.

## PDF types

Authenticated routes are available under `/api/pdfs`:

- `GET /api/pdfs/client/:id`
- `GET /api/pdfs/case/:id`
- `GET /api/pdfs/service/:id`
- `GET /api/pdfs/reports`
- `GET /api/pdfs/financial`

### Client PDF

Includes client information, related cases, related services, and recent client activity. Financial values are included only for Admin/Lawyer.

### Case PDF

Includes case information, client, hearings, files metadata, and financial summary/payments/expenses only for Admin/Lawyer.

### Service PDF

Includes service information, client, and financial summary/payments/expenses only for Admin/Lawyer.

### Financial PDF

Protected by server-side Admin/Lawyer authorization before generation.

### Reports PDF

Provides the shared operational report PDF output. Financial PDF generation is separately protected.

## Attachments

PDFs list attachment metadata where available. Actual attachments are not embedded into PDFs.

## Offline/client installation

The PDF runtime dependencies are declared in both the root Electron application package and backend package so the Electron packaged application can resolve them from its bundled `node_modules`.

The build configuration already packages `node_modules/**/*`, and the Cairo fonts are already inside the packaged `frontend/**/*` tree.

## Dependency installation required

The repository package manifests were updated, but the existing lockfiles must be regenerated by running npm install in the project environment before using `npm ci` or producing the final installer.

Recommended local commands:

```powershell
npm install
cd backend
npm install
cd ..
```

Do not use `npm ci` until the lockfiles contain the new PDF dependencies.
